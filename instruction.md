# Система управления цифровыми табло (Digital Signage)

**Стек:** Node.js (сервер), PostgreSQL (БД), Smart TV (клиенты через браузер)

---

## 1. Серверная часть

**REST API:**
- Авторизация (JWT) для админ-панели
- CRUD плейлистов
- CRUD медиа-контента (загрузка файлов, хранение в `/media`)
- Управление экранами (регистрация, обновление статуса, привязка плейлистов)
- Heartbeat-эндпоинт для ТВ (интервал ~30 сек)

**WebSocket:**
- Push-уведомления в админ-панель (статус экранов онлайн/оффлайн)
- Команды экранам (смена плейлиста, перезагрузка)

---

## 2. Админ-панель (веб-интерфейс)

**Страницы:**

| Страница | Функционал |
|----------|------------|
| `/login` | Авторизация |
| `/screens` | **Единая страница экранов и мониторинга:** карточки (4:3), статус онлайн/оффлайн, имя, IP, последний heartbeat, смена плейлиста (индивидуально/группой), превью текущего контента |
| `/playlists` | Создание/редактирование плейлистов |
| `/media` | Загрузка/удаление медиафайлов |

### Регистрация новых экранов

Новые устройства **не добавляются вручную** — регистрация происходит автоматически:

1. Администратор создаёт ссылку вида `http://server:port/display/:screenId` в админ-панели
2. Ссылка открывается в браузере Smart TV
3. ТВ отправляет первый `register` сигнал на сервер через WebSocket
4. Экран автоматически появляется в админ-панели на странице `/screens`
5. Сервер присваивает статус «Ожидание» до первого heartbeat
6. После первого heartbeat статус меняется на «Онлайн»

**Повторное подключение:**
- Если ТВ перезагружается или теряет соединение — он автоматически переподключается по тому же `screenId`
- Все настройки (имя, плейлист) сохраняются в БД

---

## 3. Клиент (Smart TV)

- Веб-страница `http://server:port/display/:screenId`
- Автовоспроизведение плейлиста в цикле
- Скрытие курсора, отключение контекстного меню
- Отправка heartbeat на сервер (30 сек)
- Автопереподключение при потере связи

### Автоустановка ffmpeg

**Источник:** Официальный билд с GitHub Releases

**Алгоритм:**
```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Проверка PATH  │────►│  Скачивание     │────►│  Распаковка     │
│  (ffmpeg.exe)   │     │  (HTTPS)        │     │  в /bin/ffmpeg  │
└─────────────────┘     └─────────────────┘     └────────┬────────┘
                                                         │
                          ┌──────────────────────────────┘
                          ▼
┌─────────────────┐     ┌─────────────────┐
│  Готово         │◄────│  Проверка       │
│  (версия > 5.0) │     │  (ffmpeg -version)│
└─────────────────┘     └─────────────────┘
```

**Детали реализации:**

1. **Проверка существующей установки:**
   - Поиск `ffmpeg.exe` в системном `PATH`
   - Если найден → проверка версии (`ffmpeg -version`)
   - Если версия ≥5.0 → используется системный
   - Если не найден или версия старая → скачивание

2. **Скачивание:**
   - URL: `https://github.com/BtbN/FFmpeg-Builds/releases/latest/download/ffmpeg-master-latest-win64-gpl.zip`
   - Размер: ~100 МБ
   - Индикация прогресса в установщике

3. **Распаковка:**
   - Извлечение в `%PROGRAMFILES%\DigitalSignage\bin\ffmpeg.exe`
   - Добавление пути в системную переменную `PATH` (опционально)
   - Копирование необходимых DLL

4. **Верификация:**
   - Запуск `ffmpeg -version` для проверки
   - Сохранение пути в `.env` файл: `FFMPEG_PATH=C:\Program Files\DigitalSignage\bin\ffmpeg.exe`

### Регистрация Windows-сервиса

**Инструмент:** NSSM (Non-Sucking Service Manager) или node-windows

**Команда регистрации:**
```batch
nssm install DigitalSignage "C:\Program Files\DigitalSignage\node.exe" "server.js"
nssm set DigitalSignage DisplayName "Digital Signage Server"
nssm set DigitalSignage StartService SERVICE_AUTO_START
nssm set DigitalSignage DependOnService PostgreSQL
nssm start DigitalSignage
```

### Файлы установщика

| Файл | Описание |
|------|----------|
| `Install.ps1` | **Единый CLI-установщик** — единственная точка входа |
| `setup.iss` | Скрипт Inno Setup для создания `setup.exe` |
| `download-ffmpeg.ps1` | PowerShell скрипт загрузки ffmpeg |
| `generate-password.js` | Генерация хэша пароля админа |

### Требования к установщику

- PowerShell 5.1+ (встроен в Windows 7+)
- Логирование всех шагов в `%TEMP%\DigitalSignage-Setup.log`
- Создание ярлыков на рабочем столе и в меню Пуск (через setup.iss)
- Регистрация как Windows-сервиса при наличии прав администратора
- Поддержка кириллицы через UTF-8

## 5. Конвертация видео в GIF

### Проблема
Браузеры Smart TV (особенно старые версии WebOS, Tizen) имеют ограниченную поддержку видеоформатов:
- Отсутствие кодеков H.264/H.265
- Проблемы с контейнерами MP4/WebM
- Аппаратные ограничения декодирования

### Решение
Все загружаемые видеофайлы автоматически конвертируются в формат GIF с сохранением длительности оригинала.

### Процесс конвертации

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐     ┌─────────────┐
│  Загрузка   │────►│  Конвертация │────►│  Сохранение │────►│  Доступно   │
│   видео     │     │  (ffmpeg)    │     │     GIF     │     │  в плейлисте│
└─────────────┘     └──────────────┘     └─────────────┘     └─────────────┘
```

### API эндпоинты

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `POST` | `/api/media/upload` | Загрузка видео (MP4, AVI, MKV, WebM) |
| `GET` | `/api/media/:id/status` | Статус конвертации (`pending`, `processing`, `completed`, `failed`) |
| `GET` | `/api/media/:id/progress` | Прогресс конвертации в процентах |

### Параметры конвертации

| Параметр | Значение по умолчанию | Описание |
|----------|----------------------|----------|
| `max_width` | 1920 | Максимальная ширина GIF (сохранение аспекта) |
| `fps` | 15 | Кадров в секунду (баланс качество/размер) |
| `quality` | 8 | Уровень качества ffmpeg (1-12) |
| `preserve_audio` | false | Аудио не сохраняется (GIF не поддерживает) |

### Структура хранения

```
/media/
├── original/          # Исходные файлы
│   └── video_123.mp4
├── converted/         # GIF файлы
│   └── video_123.gif
└── metadata/          # JSON с метаданными
    └── video_123.json
```

**metadata/video_123.json:**
```json
{
  "id": "video_123",
  "original_name": "presentation.mp4",
  "duration": 45.5,
  "original_format": "mp4",
  "gif_path": "/media/converted/video_123.gif",
  "file_size": 15728640,
  "dimensions": { "width": 1920, "height": 1080 },
  "conversion_status": "completed",
  "created_at": "2026-04-02T10:00:00Z",
  "converted_at": "2026-04-02T10:02:30Z"
}
```

### Очередь конвертации

- Конвертация выполняется в фоновом режиме (worker-процесс)
- Поддержка очереди при одновременной загрузке нескольких файлов
- Приоритет: первый файл в очереди обрабатывается первым
- Уведомление в админ-панель по завершении (WebSocket)

### Пример команды конвертации

### Вызов из Node.js

```javascript
import ffmpeg from 'fluent-ffmpeg';

function convertToGif(inputPath, outputPath, options) {
  return new Promise((resolve, reject) => {
    ffmpeg(inputPath)
      .outputOptions([
        `-vf fps=${options.fps || 15},scale=${options.maxWidth || 1920}:-1:flags=lanczos`,
        `-quality ${options.quality || 8}`
      ])
      .on('progress', (progress) => {
        // Отправка прогресса в админ-панель через WebSocket
        emitProgress(progress.percent);
      })
      .on('end', () => resolve(outputPath))
      .on('error', reject)
      .save(outputPath);
  });
}
```

- При `true` → загружается оригинальное видео
- При `false` → всегда конвертируется в GIF
- Определение поддержки через user-agent экрана

## 6. Механизм смены плейлистов

### Архитектура взаимодействия

```
┌─────────────┐      WebSocket       ┌─────────────┐
│ Админ-панель│ ───────────────────► │   Сервер    │
└─────────────┘                      └────────────┘
                                            │
                          ┌─────────────────┼─────────────────┐
                          │                 │                 │
                          ▼                 ▼                 ▼
                   ┌────────────┐   ┌────────────   ┌────────────┐
                   │   ТВ №1    │   │   ТВ №2    │   │   ТВ №N    │
                   │ (screenId) │   │ (screenId) │   │ (screenId) │
                   └────────────┘   └────────────┘   └────────────┘
```

### API эндпоинты

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `PATCH` | `/api/screens/:screenId/playlist` | Сменить плейлист у одного экрана |
| `PATCH` | `/api/screens/bulk-playlist` | Сменить плейлист у группы экранов |
| `GET` | `/api/display/:screenId/config` | Получить текущую конфигурацию (при старте/переподключении) |

### WebSocket события

**Клиент → Сервер:**
- `register` — регистрация экрана при подключении `{ screenId, timestamp }`
- `heartbeat` — сигнал активности `{ screenId, timestamp }`
- `ack` — подтверждение получения команды `{ commandId, status }`

**Сервер → Клиент:**
- `playlist-change` — команда смены плейлиста `{ playlistId, mediaList, commandId }`
- `ping` — запрос статуса (если нет heartbeat > 60 сек)

### Поток данных при смене плейлиста

1. **Админ выбирает плейлист** → клик «Применить»
2. **Сервер** находит все WebSocket-соединения для указанных `screenId`
3. **Сервер** отправляет событие `playlist-change` с полным списком медиа
4. **ТВ** получает событие, кэширует список, начинает воспроизведение
5. **ТВ** отправляет `ack` с подтверждением
6. **Сервер** обновляет `last_playlist_change` в БД
7. **Админ-панель** получает обновление статуса через WebSocket

### Обработка офлайн-сценариев

- Если ТВ офлайн → команда сохраняется в БД (`pending_commands`)
- При подключении ТВ запрашивает `/api/display/:screenId/config`
- Сервер возвращает актуальный плейлист + все pending-команды
- ТВ выполняет команды, отправляет подтверждения

### Структура БД

```sql
-- Таблица экранов
CREATE TABLE screens (
  id UUID PRIMARY KEY,
  name VARCHAR(255),
  ip_address INET,
  playlist_id UUID REFERENCES playlists(id),
  last_heartbeat TIMESTAMP,
  status VARCHAR(50), -- 'online', 'offline', 'error'
  created_at TIMESTAMP DEFAULT NOW()
);

-- Таблица отложенных команд
CREATE TABLE pending_commands (
  id UUID PRIMARY KEY,
  screen_id UUID REFERENCES screens(id),
  command_type VARCHAR(50), -- 'playlist_change', 'restart', 'settings_update'
  payload JSONB,
  created_at TIMESTAMP DEFAULT NOW(),
  executed_at TIMESTAMP,
  status VARCHAR(50) -- 'pending', 'executed', 'failed'
);
```

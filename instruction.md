# Система управления цифровыми табло (Digital Signage)

**Стек:** Node.js (Express + WebSocket), PostgreSQL (БД), Smart TV (клиенты через браузер)

---

## 1. Серверная часть

**REST API:**
- Авторизация (JWT) для админ-панели
- CRUD плейлистов (с переупорядочиванием элементов и настройкой длительности)
- CRUD медиа-контента (загрузка файлов, хранение в `/media`)
- Управление экранами (регистрация, обновление статуса, привязка плейлистов, группировка)
- CRUD групп экранов (логическое объединение по зонам)
- CRUD сценариев (автоматическое переключение плейлистов по расписанию)
- Глобальные настройки (файл `settings.json`)
- Heartbeat-эндпоинт для ТВ (интервал ~30 сек)

**WebSocket (`/ws`):**
- Push-уведомления в админ-панель (статус экранов онлайн/оффлайн, конвертация)
- Команды экранам (смена плейлиста, перезагрузка)
- Очередь отложенных команд для офлайн-экранов

**Логирование:**
- `logs/access.log` — все HTTP-запросы
- `logs/auth.log` — действия авторизации
- `logs/error.log` — ошибки сервера и конвертации

## 2. Админ-панель (веб-интерфейс)

**Страницы:**

| Страница | Функционал |
|----------|------------|
| `/admin/login.html` | Авторизация |
| `/admin/screens.html` | Управление экранами: карточки, статус онлайн/оффлайн, имя, IP, последний heartbeat, смена плейлиста (индивидуально/группой), привязка к группе |
| `/admin/playlists.html` | Создание/редактирование/удаление плейлистов, переупорядочивание элементов, настройка длительности |
| `/admin/media.html` | Загрузка/удаление медиафайлов, мониторинг конвертации видео→GIF |
| `/admin/scenarios.html` | Сценарии: автоматическое переключение плейлистов по дням недели/времени/датам, приоритеты, группы экранов |
| `/admin/settings.html` | Глобальные настройки (медиа по умолчанию и др.) |

### Регистрация новых экранов

Новые устройства **не добавляются вручную** — регистрация происходит автоматически:

1. Администратор открывает ссылку вида `http://server:port/display/:screenId` на Smart TV
2. ТВ отправляет первый `register` сигнал на сервер через WebSocket
3. Экран автоматически появляется в админ-панели на странице `/admin/screens.html`
4. Сервер присваивает статус «Ожидание» до первого heartbeat
5. После первого heartbeat статус меняется на «Онлайн»

**Повторное подключение:**
- Если ТВ перезагружается или теряет соединение — он автоматически переподключается по тому же `screenId`
- Все настройки (имя, плейлист, группа) сохраняются в БД

## 3. Клиент (Smart TV)

- Веб-страница `http://server:port/display/:screenId`
- Автовоспроизведение плейлиста в цикле
- Скрытие курсора, отключение контекстного меню
- Отправка heartbeat на сервер (30 сек)
- Автопереподключение при потере связи
- Получение и выполнение pending-команд при подключении

## 4. Установщик (Windows)

**Формат:** Единый CLI-установщик `Install.ps1` (PowerShell 5.1+)

### Запуск

```powershell
# Из проводника — правый клик → «Выполнить в PowerShell»
# Или из консоли:
powershell -File Install.ps1
```

### Возможности установщика

| Возможность | Описание |
|-------------|----------|
| **Цветной вывод** | ANSI-цвета, прогресс-бары, ASCII-логотип |
| **Интерактивное меню** | Навигация стрелками ↑↓, выбор Enter |
| **Маска пароля** | Скрытый ввод с символом `*` для пароля PostgreSQL и админа |
| **7 шагов установки** | Node.js → npm → каталоги → ffmpeg → PostgreSQL → admin → сервис |
| **Автоматический сервис** | При правах администратора — регистрация Windows-сервиса через NSSM (автозагрузка) |
| **Автозагрузка ffmpeg** | Скачивание и установка ffmpeg из GitHub Releases (~100 МБ) |
| **Логирование** | Полный лог в `%TEMP%\DigitalSignage-Setup.log` |

### Процесс установки

| Шаг | Описание |
|-----|----------|
| 1 | Проверка наличия Node.js (≥18.x) |
| 2 | Установка npm-зависимостей |
| 3 | Создание служебных каталогов (media, logs) |
| 4 | Скачивание и установка ffmpeg (если не найден) |
| 5 | Настройка PostgreSQL: создание БД и пользователя `digitalsignage` |
| 6 | Создание таблиц и учётной записи admin |
| 7 | Завершение: маркер INSTALL_OK, ярлык, регистрация сервиса (NSSM) |

### Регистрация Windows-сервиса

**Инструмент:** NSSM (Non-Sucking Service Manager) — загружается автоматически

**Параметры сервиса:**
- Имя: `DigitalSignage`
- Отображаемое имя: `Digital Signage Server`
- Автозапуск: `SERVICE_AUTO_START`
- Зависимость: `PostgreSQL`
- Логи: `logs/service-stdout.log`, `logs/service-stderr.log`

## 5. Конвертация видео в GIF

### Проблема
Браузеры Smart TV (особенно старые версии WebOS, Tizen) имеют ограниченную поддержку видеоформатов:
- Отсутствие кодеков H.264/H.265
- Проблемы с контейнерами MP4/WebM
- Аппаратные ограничения декодирования

### Решение
Все загружаемые видеофайлы автоматически конвертируются в формат GIF с сохранением длительности оригинала.

### Процесс конвертации

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐     ┌─────────────┐
│  Загрузка   │────►│  Конвертация │────►│  Сохранение │────►│  Доступно   │
│   видео     │     │  (ffmpeg)    │     │     GIF     │     │  в плейлисте│
└─────────────┘     └──────────────┘     └─────────────┘     └─────────────┘
```

### Параметры конвертации

| Параметр | Значение | Описание |
|----------|----------|----------|
| `max_width` | 1920 | Максимальная ширина GIF (сохранение аспекта) |
| `fps` | 5–15 (адаптивно) | Вычисляется из длительности: `min(15, max(5, ceil(300/duration)))` |
| Очередь | Последовательная | Одно видео за раз, прогресс через WebSocket |

### Структура хранения

```
/media/
├── original/          # Исходные файлы
│   └── {uuid}.mp4
├── converted/         # GIF файлы
│   └── {uuid}.gif
└── metadata/          # JSON с метаданными
    └── {uuid}.json
```

### Ограничения

| Параметр | Значение |
|----------|----------|
| Макс. размер файла | 500 МБ |
| Макс. разрешение | 1920×1080 |
| Поддерживаемые форматы | MP4, AVI, MKV, WebM, MOV, JPG, PNG, SVG |

### Альтернативный режим (видео)

При `USE_VIDEO_IF_SUPPORTED=true` сервер отдаёт оригинальное видео вместо GIF.
Флаг `false` — всегда конвертируется в GIF.

## 6. Механизм смены плейлистов

### Поток данных

1. **Админ выбирает плейлист** → клик «Применить»
2. **Сервер** находит все WebSocket-соединения для указанных `screenId`
3. **Сервер** отправляет событие `playlist-change` с полным списком медиа
4. **ТВ** получает событие, кэширует список, начинает воспроизведение
5. **ТВ** отправляет `ack` с подтверждением
6. **Сервер** обновляет `pending_commands` в БД
7. **Админ-панель** получает обновление статуса через WebSocket

### Обработка офлайн-сценариев

- Если ТВ офлайн → команда сохраняется в БД (`pending_commands`)
- При подключении ТВ запрашивает `/api/display/:screenId/config`
- Сервер возвращает актуальный плейлист + все pending-команды
- ТВ выполняет команды, отправляет подтверждения

### Контент по умолчанию

Если плейлист снят (`playlist_id = NULL`), экран показывает:
1. Индивидуальное `default_media_id` экрана (если задано)
2. Глобальное медиа из настроек (`settings.defaultMediaId`)

## 7. Сценарии (расписание)

Сценарии позволяют автоматически переключать плейлисты по расписанию.

### Параметры сценария

| Параметр | Описание |
|----------|----------|
| `playlist_id` | Какой плейлист применить |
| `group_id` | К какой группе применить (NULL = ко всем экранам) |
| `days_of_week` | Дни недели (1=Mon..7=Sun), например `"1,2,3,4,5"` |
| `time_from` / `time_to` | Временной диапазон в течение дня |
| `date_from` / `date_to` | Диапазон дат |
| `enabled` | Включён/выключен |
| `priority` | Приоритет (больше = важнее) |

### Проверка сценариев
- Автоматическая: каждые 60 секунд (таймер на сервере)
- Принудительная: `POST /api/scenarios/check` из админ-панели

## 10. Схема базы данных

### Таблицы

| Таблица | Ключевые поля | Описание |
|---------|---------------|----------|
| `admins` | `id`, `login`, `password_hash`, `must_change_password` | Учётные записи администраторов |
| `media` | `id`, `original_name`, `mime_type`, `original_path`, `gif_path`, `duration_seconds`, `conversion_status` | Медиафайлы с метаданными конвертации |
| `playlists` | `id`, `name`, `created_at`, `updated_at` | Плейлисты |
| `playlist_items` | `id`, `playlist_id`, `media_id`, `order`, `duration_seconds` | Элементы плейлистов (связь media ↔ playlists) |
| `screen_groups` | `id`, `name` | Группы экранов |
| `screens` | `id`, `name`, `ip_address`, `group_id`, `playlist_id`, `default_media_id`, `status`, `last_heartbeat` | Экраны (Smart TV) |
| `scenarios` | `id`, `name`, `playlist_id`, `group_id`, `days_of_week`, `time_from`, `time_to`, `date_from`, `date_to`, `enabled`, `priority` | Сценарии (расписание) |
| `pending_commands` | `id`, `screen_id`, `command_type`, `payload`, `status`, `created_at`, `executed_at` | Отложенные команды для офлайн-экранов |
| `event_logs` | `id`, `screen_id`, `event_type`, `message`, `created_at` | Журнал событий экранов |

Полная схема — в `database/init.sql`.

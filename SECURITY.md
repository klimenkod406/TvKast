# Политика безопасности

## Учётные данные по умолчанию

| Роль | Логин | Пароль | Примечание |
|------|-------|--------|------------|
| Admin | admin | задаётся при установке | Флаг `must_change_password` установлен по умолчанию |

## Смена пароля
1. При первом входе администратор должен сменить пароль (`must_change_password = true`).
2. Требования к паролю: не менее 8 символов (проверка при установке).
3. Рекомендуется использовать 12+ символов, включая цифры и спецсимволы.

## Доступ к БД
- Пользователь приложения: `digitalsignage`
- БД: `digitalsignage_db`
- Порт: `5432`
- Суперпользователь: `postgres` (требуется только при установке)
- Рекомендуется: доступ только с localhost/внутренней сети

## JWT-аутентификация
- Токен JWT хранится только на сервере в переменной `JWT_SECRET`.
- Срок действия токена: 12 часов.
- Все API-эндпоинты админ-панели требуют заголовок `Authorization: Bearer <token>`.

## WebSocket-безопасность
- Подписка администратора (`admin-subscribe`) не требует дополнительной авторизации — убедитесь, что сервер недоступен извне без защиты.
- Регистрация экрана (`register`) открыта — любой клиент может зарегистрироваться, зная URL `/ws`.

## Файловая безопасность
- Максимальный размер загружаемого файла: 500 МБ.
- Файлы хранятся в `/media` — убедитесь, что директория не доступна для прямой загрузки без авторизации.
- Исходные файлы переименовываются в UUID для предотвращения path traversal.

## Логирование

| Лог | Содержание |
|-----|------------|
| `logs/access.log` | Все HTTP-запросы (метод, URL, IP, статус, длительность) |
| `logs/auth.log` | Действия авторизации (логин, результат) |
| `logs/error.log` | Ошибки сервера, конвертации, аутентификации |

**Рекомендации:**
- Логи авторизации хранить не менее 90 дней.
- Логи heartbeat — не менее 30 дней.
- Регулярно ротировать файлы логов.
